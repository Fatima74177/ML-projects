# API_DOCUMENTATION.md — EEF Platform

Full interactive, always-up-to-date documentation is auto-generated by
FastAPI at:
- **Swagger UI:** `GET /docs`
- **ReDoc:** `GET /redoc`
- **Raw OpenAPI schema:** `GET /openapi.json`

Every endpoint below has a request schema, response schema, and structured
error responses defined directly in code (see each router's `summary=` /
`description=` and the `ErrorResponse` shape) — this document is a
human-readable index, not a duplicate spec.

All endpoints are prefixed with `/api/v1` unless noted. Authenticate with
`POST /api/v1/auth/login` (form-encoded `username`/`password`) and send
`Authorization: Bearer <token>` on subsequent requests.

Requests to `/api/v1` are limited to `RATE_LIMIT_PER_MINUTE` per client IP
(default: 120). Exceeding the limit returns HTTP `429`, `error_code:
RATE_LIMITED`, and a `Retry-After` header. Redis is used when enabled;
otherwise the limit is process-local and intended for development.

## Standard Error Shape

```json
{
  "success": false,
  "error_code": "VALIDATION_ERROR",
  "message": "Invalid request payload.",
  "details": {}
}
```

## Identity Verification (`/identity`)
| Method | Path | Role | Description |
|---|---|---|---|
| POST | `/identity/verify` | ANALYST+ | Full pipeline: OCR→face→liveness→trust→fraud→decision |
| GET | `/identity/{id}` | any | Get one verification session |
| GET | `/identity` | any | List recent verification sessions |

`verify` returns exactly the shape specified in the brief: `verification_id,
status, identity_match_score, liveness_score, document_score, risk_score,
trust_score, fraud_indicators, explanation, timestamp`.

## Example: Full Verification Call

```bash
curl -X POST http://localhost:8000/api/v1/identity/verify \
  -H "Authorization: Bearer $TOKEN" \
  -F "full_name=Jane Demo" \
  -F "document_type=NATIONAL_ID" \
  -F "document=@data/demo/documents/demo_national_id_1.png" \
  -F "selfie=@data/demo/images/face_a_1.png"
```
